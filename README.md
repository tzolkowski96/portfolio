# Portfolio — Tobin Zolkowski

Personal site for Tobin Zolkowski: data analyst, reporting & BI, data journalism.
A hand-built static site with **no build step and no runtime dependencies** — just
HTML, CSS, and a little vanilla JavaScript, served straight off GitHub Pages.

**Live:** https://tzolkowski96.github.io/portfolio/

## Structure

```
portfolio/
├── index.html                  Markup only — content and structure
├── css/
│   ├── base.css                Design tokens, resets, typography, utilities
│   ├── layout.css              Header, hero/record, section scaffold, footer
│   ├── components.css          About, metrics, dashboard, tables, work log, writing, connect
│   └── responsive.css          Breakpoint overrides (mobile + large screens)
├── js/
│   ├── readout.js              Scroll progress + Central-time clock
│   ├── nav.js                  Mobile menu + scroll-spy active link
│   ├── feed.js                 Hydrates the writing feed from feed.json
│   └── contact.js              Formspree AJAX submit
├── scripts/
│   └── build_feed.py           Builds feed.json from the Medium RSS feed
├── .github/workflows/
│   └── medium-feed.yml         Scheduled Action: refresh the feed every 6 hours
├── og-image.png                Social share card (1200×630, rendered at 2×)
└── feed.json                   Generated by the Action — not committed by hand
```

Each JS file is a self-contained IIFE that wires up one feature and no-ops if its
elements aren't on the page, so they're independent and load in any order
(`defer`). CSS is split by concern and loaded base → layout → components →
responsive to keep the cascade predictable.

## Local development

No tooling required. Serve the folder over HTTP (needed so `feed.js` can `fetch`
`feed.json`; opening `index.html` via `file://` works too, the feed just falls
back to the posts baked into the HTML):

```sh
python3 -m http.server 8000
# then open http://localhost:8000
```

## The writing feed

The Writing section shows the latest Medium posts. Rather than hand-editing the
list, a scheduled GitHub Action keeps it current:

1. `scripts/build_feed.py` reads the Medium RSS feed, pulls a clean subtitle
   (`og:description`) for each post, drops anything on its `SKIP` list, and
   writes the six newest to `feed.json`.
2. `.github/workflows/medium-feed.yml` runs that script every 6 hours (and on
   demand from the Actions tab) and commits `feed.json` when it changes.
3. On load, `feed.js` fetches `feed.json` and re-renders the feed. Until the file
   exists, the posts embedded in `index.html` show instead — so the section is
   never empty.

To change which posts are filtered out, edit the `SKIP` list in
`scripts/build_feed.py`. Nothing else needs touching.

## Deployment

Hosted on GitHub Pages from the `main` branch, root folder. An empty `.nojekyll`
tells Pages to serve the files as-is rather than running them through Jekyll.

First-time setup after pushing:

1. **Settings → Pages** → deploy from `main`, root folder.
2. **Settings → Actions → General → Workflow permissions** → Read and write
   (so the feed Action can commit `feed.json`).
3. **Actions tab** → run "Refresh Medium feed" once to generate the first
   `feed.json`.
4. Send a test message through the contact form and confirm the Formspree email.

If the repository is ever renamed or moved off `tzolkowski96.github.io/portfolio/`,
update the three absolute URLs in `index.html`'s `<head>`: `canonical`, `og:url`,
and `og:image`.
